# Информационная система управления недвижимостью (ИСУН)

Стек: **React** (frontend), **Django REST Framework** (backend), **PostgreSQL**, развертывание в **Docker**.

## Для чего нужна система

Представьте бизнес-центр или портфель из нескольких квартир: много арендаторов, у каждого свой договор и дата оплаты, у кого-то сломалась лампочка, у кого-то течет кран. Ведение всего этого в Excel или блокноте быстро приводит к хаосу.

**ИСУН** — единый личный кабинет для управления этим процессом. Система автоматизирует три направления:

1. **Учет:** что сдаем, кому сдаем, на каких условиях (объекты, арендаторы, договоры).
2. **Финансы:** кто сколько должен, заплатил ли, история начислений и оплат.
3. **Сервис:** заявки на ремонт/обслуживание, назначение исполнителей, статусы выполнения.

В системе три типа пользователей с разным доступом.

## Роли и функционал

### Администратор / Менеджер (сотрудник компании)

Главный пользователь: видит все данные и управляет процессами.

**За что отвечает:** заполнение базы, заключение договоров, контроль платежей, назначение исполнителей по заявкам.

| Раздел | Функционал |
|--------|------------|
| **Главная (дашборд)** | Сводка: сколько объектов свободно/арендовано, активных арендаторов и договоров, суммы по платежам, открытые заявки. |
| **Объекты** | Список помещений, фильтры по статусу и типу, поиск. Добавление и редактирование объектов, статусы (свободно, арендовано, на обслуживании и т.д.). |
| **Арендаторы** | Карточки арендаторов, поиск, статусы. |
| **Договоры** | Список договоров аренды. Создание договора: выбор объекта (с проверкой занятости) и арендатора, даты, сумма, при необходимости скан договора. |
| **Платежи** | Список начислений и оплат. Отметка оплаты (проведение платежа), фильтры по статусу и периоду. |
| **Заявки** | Все заявки от арендаторов. Назначение ответственного, смена статуса (в работе, выполнено), комментарии. |
| **Отчеты** | Сводки по объектам, платежам, заявкам. Экспорт платежей в CSV и Excel. |
| **Аудит** (только админ) | Журнал действий в системе: кто и что создал/изменил/удалил. |
| **Пользователи** (только админ) | Управление учетными записями и ролями. |

---

### Арендатор (клиент)

Работает только со своими данными в личном кабинете.

**За что отвечает:** своевременная оплата и информирование о проблемах (заявки на ремонт/обслуживание).

| Раздел | Функционал |
|--------|------------|
| **Главная** | Краткая сводка по своим договорам и платежам (если доступно). |
| **Мои объекты** | Список помещений, которые арендатор арендует по действующим договорам: адрес, срок, сумма. |
| **Мои платежи** | Начисления по аренде (аренда, коммунальные и т.д.): сумма, срок, статус (ожидает оплаты / оплачено / просрочено). История платежей. |
| **Мои заявки** | Список своих заявок на обслуживание и их статусы (новая, в работе, выполнено и т.д.), комментарии. |
| **Создать заявку** | Форма: выбор объекта (из своих), категория (сантехника, электрика и т.д.), тема, описание, приоритет. После отправки заявка отображается в «Мои заявки» со статусом «Принято» и далее. |
| **Профиль** | Изменение имени, телефона, смена пароля. |

Онлайн-оплата через интеграцию с банком в текущей версии не реализована: арендатор видит счета и может оплачивать их вне системы; отметку об оплате вносит менеджер/администратор.

## Кратко по возможностям системы

- Объекты недвижимости (типы, статусы, удобства)
- Арендаторы и договоры аренды
- Платежи (аренда, коммунальные и др.), проведение оплат
- Заявки на обслуживание с комментариями и статусами
- Отчеты и экспорт в CSV/Excel (администратор/менеджер)
- Журнал аудита и управление пользователями (администратор)
- Раздельный интерфейс: полный доступ для сотрудников, личный кабинет для арендатора

## Запуск через Docker (рекомендуется)

### Требования

- Установленные [Docker](https://docs.docker.com/get-docker/) и [Docker Compose](https://docs.docker.com/compose/install/)

### Шаги

1. Клонируйте репозиторий и перейдите в каталог проекта:
   ```bash
   cd c:\Users\goonthug\PycharmProjects\PythonProject3
   ```

2. Создайте файл с переменными окружения (один раз):
   ```bash
   copy .env.example .env
   ```
   При необходимости отредактируйте `.env` (пароль БД, `SECRET_KEY` и т.д.).

3. Соберите образы и запустите контейнеры:
   ```bash
   docker-compose up --build -d
   ```

4. Дождитесь запуска (около 30–60 секунд). При первом запуске выполняются миграции и заполнение тестовыми данными.

5. Откройте в браузере:
   - **Фронтенд (интерфейс):** http://localhost:3000
   - **Бэкенд API (документация):** http://localhost:8000/api/docs/

### Остановка

```bash
docker-compose down
```

Данные БД сохраняются в Docker-томе. Чтобы удалить и их:

```bash
docker-compose down -v
```

## Запуск без Docker (разработка)

### Бэкенд

1. Установите PostgreSQL и создайте БД и пользователя (как в `.env`).

2. В каталоге `backend`:
   ```bash
   cd backend
   python -m venv venv
   venv\Scripts\activate
   pip install -r requirements.txt
   copy ..\.env.example .env
   ```
   Заполните `.env`: укажите `POSTGRES_HOST=localhost` и реальные пароли.

3. Миграции и тестовые данные:
   ```bash
   python manage.py migrate
   python manage.py seed_data
   ```

4. Запуск сервера:
   ```bash
   python manage.py runserver
   ```
   API: http://localhost:8000

### Фронтенд

1. В каталоге `frontend`:
   ```bash
   cd frontend
   npm install
   npm run dev
   ```
   Интерфейс: http://localhost:3000 (прокси к API на порт 8000 настроен в `vite.config.js`).

## Структура проекта

```
PythonProject3/
  docker-compose.yml    # Сервисы: db, backend, frontend
  .env.example
  backend/
    config/             # Настройки Django
    apps/
      users/            # Авторизация, JWT, пользователи
      properties/       # Объекты недвижимости
      tenants/          # Арендаторы и договоры
      payments/         # Платежи и категории
      service_requests/ # Заявки на обслуживание
      audit/            # Журнал аудита
      reports/         # Отчеты и экспорт
    manage.py
    requirements.txt
    Dockerfile
    entrypoint.sh
  frontend/
    src/
      api/              # HTTP-клиент (axios)
      context/          # AuthContext
      components/
      pages/
    index.html
    package.json
    vite.config.js
    Dockerfile
    nginx.conf
```

После перезагрузки страницы сессия не сбрасывается: используется JWT (access + refresh), токены хранятся в `localStorage`, refresh выполняется автоматически.
